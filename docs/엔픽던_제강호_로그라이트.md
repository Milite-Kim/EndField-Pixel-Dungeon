# 제강호 (Jiganghao) — 로그라이트 메타 진행 설계

> 런(탐색)을 반복할수록 영구적으로 쌓이는 거점 시스템.
> 로그라이크(매 런 완전 초기화) → **로그라이트**(런을 넘어 진행도 축적)로 전환하는 핵심 요소.
>
> 상태: 🟡 설계 단계 (미구현). 참고: 명픽던의 정보증명서/로도스 아일랜드 구조 — `docs/` 외부 `reference/`

---

## 1. 개요

**제강호(制鋼號)** 는 엔드필드 세계관에서 주인공 일행이 사용하는 **거점 우주선**이다.
플레이어는 탐색(런)에서 얻은 **항공 건축 재료**를 제강호에 투자해 영구 성장을 누적한다.

```
탐색(런) ──[보스 처치 → 항공 건축 재료]──▶ 제강호
   ▲                                          │
   └──[선실 효과 / 제작 아이템 / 지원 효과]────┘
```

### 설계 원칙

| 원칙 | 내용 |
|------|------|
| **사망해도 재화는 유지** | 재료는 획득 즉시 영구 저장소에 적립. 런 실패가 완전한 손실이 되지 않도록 |
| **선택 압박 유지** | 재화는 단일 축(항공 건축 재료). 선실·업그레이드·제작이 같은 자원을 놓고 경쟁 |
| **파워 상한 존재** | 영구 강화가 "충분히 쌓이면 자동 클리어"가 되지 않도록 상한/체감 곡선 설정 |
| **런 내 실력 우선** | 메타 강화는 진입 장벽 완화이지, 실력 대체재가 아님 |

---

## 2. 재화 — 항공 건축 재료

| 항목 | 내용 |
|------|------|
| 명칭 | 항공 건축 재료 |
| 성격 | **영구 재화** (런 종료·사망과 무관하게 유지) |
| 주 획득처 | **보스 처치** (A5 로댄 등 계층 보스) |
| 보조 획득처 (검토) | 미니보스 / 특정 층 도달 / 도전과제 달성 |
| 보너스 (검토) | 고난이도 옵션 활성 시 획득량 가산 (명픽던 방식) |

> **획득 즉시 적립**이 핵심이다. 인벤토리에 들고 있다가 사망 시 잃는 구조면
> 로그라이트 완충 효과가 사라진다. 아이템으로 드랍하되 **줍는 순간 영구 저장**한다.

### 탐색 재료 (별도 축)

씨앗·특수 아이템 등 **런 중 획득해 제강호로 반입**하는 재료. 4번 시스템(의뢰 제작)의 입력이며,
항공 건축 재료와는 별개 자원으로 관리한다.

---

## 3. 제강호 구조

제강호는 **선실(Room) 단위**로 확장된다.

```
제강호
├─ 선실 A (제작실)   ← 건축 재료로 '건설'
│   └─ 제작 기능 해금
├─ 선실 B (재배실)   ← 건설
│   └─ 의뢰 기능 해금
└─ 함선 업그레이드   ← 선실과 별개로 재료 투자
    └─ 탐색 중 상시 지원 효과
```

- **선실 건설** = 기능 해금 (재료 소모, 1회성)
- **함선 업그레이드** = 수치 강화 (재료 소모, 단계별 누적)

---

## 4. 시스템 상세

### 4-1. 선실 제작 (건설)

건축 재료를 소모해 제강호 내부에 선실을 건설한다. 건설된 선실은 **새로운 기능을 해금**한다.

| 항목 | 내용 |
|------|------|
| 비용 | 항공 건축 재료 (선실별 상이) |
| 효과 | 해당 선실의 기능 해금 (제작·재배·강화 등) |
| 성격 | 1회성 (한 번 지으면 영구) |
| 선행 조건 (검토) | 특정 층 도달 / 특정 보스 처치 |

**선실 후보** (미확정 — 예시)

| 선실 | 기능 |
|------|------|
| 제작실 | 4-2. 건축 재료로 소모품 제작 |
| 재배실 | 4-4. 씨앗 의뢰 → 다음 런 시작 아이템 |
| 정비실 | 4-3. 함선 업그레이드 해금/확장 |
| 통제실 (검토) | 오퍼레이터 해금·편성 관련 (기존 `OperatorRegistry`와 연계) |

### 4-2. 선실 제작 (물품 생산)

건설된 선실에서 **항공 건축 재료를 소모해 아이템을 제작**한다.

| 항목 | 내용 |
|------|------|
| 입력 | 항공 건축 재료 (일정 수량) |
| 산출 | 소모품 등 (품목 **미확정**) |
| 수령 시점 | **다음 런 시작 시 인벤토리에 지급** (검토: 즉시 보관함) |

### 4-3. 함선 업그레이드 (상시 지원 효과)

건축 재료로 제강호 자체를 강화하면, **탐색 중 제강호의 지원을 받는다**는 설정으로 이로운 효과를 얻는다.

**효과 방향 후보**

| 유형 | 예시 | 비고 |
|------|------|------|
| 시작 보급 | 시작 시 식량 +1, 물약 +1 | **권장** — 파워 인플레가 완만하고 체감이 명확 |
| 영구 스탯 | 최대 HP +N, 명중/회피 소폭 상승 | 상한 필수 |
| 편의 | 시작 소지금 증가, 감정된 아이템으로 시작 | 난이도 영향 적음 |
| 지원 (검토) | N층마다 보급 드랍 | 연출·설정 부합도 높음 |

> **밸런스 주의**: 영구 스탯 강화는 누적될수록 초반 난이도를 무의미하게 만든다.
> "시작 보급"과 "편의" 위주로 두고, 스탯 강화는 낮은 상한을 두는 편이 안전하다.

### 4-4. 의뢰 제작 (탐색 재료 → 다음 런 아이템)

탐색 중 얻은 재료를 제강호에 맡겨 **다음 런에서 완성품을 들고 시작**한다.

```
[런 N]  메밀꽃 씨앗 획득 → 제강호에 재배 의뢰
[런 N+1]  시작 인벤토리에 메밀꽃 약 1개 보유
```

| 항목 | 내용 |
|------|------|
| 입력 | 탐색 중 획득한 재료 (씨앗·특정 아이템) |
| 산출 | 대응 완성품 (약 등) |
| 수령 | **다음 런 시작 시** |
| 특징 | 시간차 보상 — 현재 런이 아닌 미래 런에 투자 |

> SPD 원본의 `씨앗 → 연금술 → 물약` 구조를 **런을 가로질러** 재해석한 형태다.
> 원본 연금술과 공존시킬지, 제강호 전용 경로로 분리할지 결정 필요.

## 5. 데이터 저장 설계

메타 진행은 **세이브 파일이 아닌 전역 파일**에 저장한다 (런 사망과 무관하게 유지).

### 기존 선례 활용

이미 `OperatorRegistry`가 동일 패턴을 쓰고 있다:

```java
public static final String REGISTRY_FILE = "operators.dat";
FileUtils.bundleFromFile(REGISTRY_FILE);   // 로드
FileUtils.bundleToFile(REGISTRY_FILE, b);  // 저장
```

### 제안 구조

**`jiganghao.dat`** (신규 전역 번들)

| 키 | 타입 | 내용 |
|----|------|------|
| `materials` | int | 보유 항공 건축 재료 |
| `builtRooms` | String[] | 건설 완료 선실 ID 목록 |
| `upgrades` | Bundle | 업그레이드 항목별 레벨 |
| `pendingItems` | Bundle[] | 다음 런 시작 시 지급할 아이템 목록 (4-2 / 4-4 산출물) |
| `storedMaterials` | Bundle | 반입된 탐색 재료 재고 |

> 단순 수치 하나(재료 개수)라면 `SPDSettings` 키로도 충분하지만,
> 선실·업그레이드·대기 아이템까지 다루므로 **전용 번들 파일이 적합**하다.

## 6. 구현 훅 (코드 지점)

| 기능 | 붙일 위치 |
|------|----------|
| 재료 획득 | 보스 `die()` — 예: `actors/mobs/endfield/Rodan.java` (부적 드랍부 참고) |
| 재료 적립 | 드랍 아이템의 `doPickUp()` → `Jiganghao.addMaterials(n)` |
| 다음 런 아이템 지급 | `actors/hero/HeroClass.initHero(Hero)` — `i.collect()` 호출부 근처 |
| 시작 보급 업그레이드 | 동일 (`initHero`) |
| 제강호 화면 | 신규 `scenes/JiganghaoScene` (→ 7절 결정 필요) |
| 영구 저장 | `Jiganghao.loadGlobal()/saveGlobal()` — `OperatorRegistry` 복제 |

## 7. 미확정 — 결정 필요 목록

| # | 항목 | 선택지 |
|---|------|--------|
| **1** | **제강호 접근 방식** | (a) 타이틀/시작 화면에서 별도 씬 (b) 던전 0층 등 인게임 공간 (c) 런 종료 직후 정산 화면 |
| 2 | 4-2와 4-4의 관계 | 별개 시스템 유지 vs 하나의 제작 시스템에 입력만 2종 |
| 3 | 제작품 수령 시점 | 다음 런 시작 시 자동 지급 vs 제강호 보관함에서 선택 반출 |
| 4 | 재료 획득처 범위 | 보스 전용 vs 미니보스·층 도달 포함 |
| 5 | 오퍼레이터 해금 연동 | 건축 재료로 해금 vs 현행 `OperatorRegistry` 조건 유지(별개) |
| 6 | 업그레이드 상한 | 항목별 최대 레벨 / 총량 상한 |
| 7 | 선실 목록 확정 | 4-1 후보 표 참조 |
| 8 | 제작 품목 확정 | 4-2 산출물 |

## 8. 구현 단계 제안

작은 것부터 굴려보며 확장하는 순서.

| 단계 | 범위 | 비고 |
|------|------|------|
| **1** | 재화만 구현 — 로댄이 재료 드랍 → 획득 시 영구 적립 → 타이틀에 보유량 표시 | 로그라이트 루프의 최소 성립 |
| **2** | 제강호 씬 + 함선 업그레이드 1종 (시작 식량 +1) | `initHero` 훅 검증 |
| **3** | 선실 건설 + 제작실(4-2) | |
| **4** | 재배실 + 의뢰 제작(4-4) | 탐색 재료 반입 구조 필요 |
| **5** | 선실 확장 / 업그레이드 다양화 | |

> 현재 A1~A5 테스트 빌드 기준으로는 **1단계만 넣어도** "로댄 처치 → 재료 획득 → 다음 런에 활용"
> 이라는 로그라이트 사이클이 성립한다.
