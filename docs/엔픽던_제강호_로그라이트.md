# 제강호 (Jiganghao) — 로그라이트 메타 진행 설계

> 런(탐색)을 반복할수록 영구적으로 쌓이는 거점 시스템.
> 로그라이크(매 런 완전 초기화) → **로그라이트**(런을 넘어 진행도 축적)로 전환하는 핵심 요소.
>
> 상태: 🟡 설계 단계 (미구현). 참고: 명픽던의 정보증명서/로도스 아일랜드 구조 — `docs/` 외부 `reference/`

---

## 1. 개요

**제강호(制鋼號)** 는 엔드필드 세계관에서 주인공 일행이 사용하는 **거점 우주선**이다.
플레이어는 탐색(런)에서 얻은 **항공 건축 재료**를 제강호에 투자해 영구 성장을 누적한다.

```
탐색(런) ──[보스 처치 → 항공 건축 재료]──▶ 제강호
   ▲                                          │
   └──[선실 효과 / 제작 아이템 / 지원 효과]────┘
```

### 설계 원칙

| 원칙 | 내용 |
|------|------|
| **사망해도 재화는 유지** | 재료는 획득 즉시 영구 저장소에 적립. 런 실패가 완전한 손실이 되지 않도록 |
| **선택 압박 유지** | 재화는 단일 축(항공 건축 재료). 선실·업그레이드·제작이 같은 자원을 놓고 경쟁 |
| **파워 상한 존재** | 영구 강화가 "충분히 쌓이면 자동 클리어"가 되지 않도록 상한/체감 곡선 설정 |
| **런 내 실력 우선** | 메타 강화는 진입 장벽 완화이지, 실력 대체재가 아님 |

---

## 2. 재화 — 항공 건축 재료

| 항목 | 내용 |
|------|------|
| 명칭 | 항공 건축 재료 |
| 성격 | **영구 재화** (런 종료·사망과 무관하게 유지) |
| 주 획득처 | **보스 처치** (A5 로댄 등 계층 보스) |
| 보조 획득처 (검토) | 미니보스 / 특정 층 도달 / 도전과제 달성 |
| 보너스 (검토) | 고난이도 옵션 활성 시 획득량 가산 (명픽던 방식) |

> **획득 즉시 적립**이 핵심이다. 인벤토리에 들고 있다가 사망 시 잃는 구조면
> 로그라이트 완충 효과가 사라진다. 아이템으로 드랍하되 **줍는 순간 영구 저장**한다.

### 탐색 재료 (별도 축)

씨앗·특수 아이템 등 **런 중 획득해 제강호로 반입**하는 재료. 4번 시스템(의뢰 제작)의 입력이며,
항공 건축 재료와는 별개 자원으로 관리한다.

---

## 3. 제강호 구조

제강호는 **선실(Room) 단위**로 확장된다.

```
제강호
├─ 선실 A (제작실)   ← 건축 재료로 '건설'
│   └─ 제작 기능 해금
├─ 선실 B (재배실)   ← 건설
│   └─ 의뢰 기능 해금
└─ 함선 업그레이드   ← 선실과 별개로 재료 투자
    └─ 탐색 중 상시 지원 효과
```

- **선실 건설** = 기능 해금 (재료 소모, 1회성)
- **함선 업그레이드** = 수치 강화 (재료 소모, 단계별 누적)

---

## 4. 시스템 상세

### 4-1. 선실 제작 (건설)

건축 재료를 소모해 제강호 내부에 선실을 건설한다. 건설된 선실은 **새로운 기능을 해금**한다.

| 항목 | 내용 |
|------|------|
| 비용 | 항공 건축 재료 (선실별 상이) |
| 효과 | 해당 선실의 기능 해금 (제작·재배·강화 등) |
| 성격 | 1회성 (한 번 지으면 영구) |
| 선행 조건 (검토) | 특정 층 도달 / 특정 보스 처치 |

**선실 후보** (미확정 — 예시)

| 선실 | 기능 |
|------|------|
| 제작실 | 4-2. 건축 재료로 소모품 제작 |
| 재배실 | 4-4. 씨앗 의뢰 → 다음 런 시작 아이템 |
| 정비실 | 4-3. 함선 업그레이드 해금/확장 |
| 통제실 (검토) | 오퍼레이터 해금·편성 관련 (기존 `OperatorRegistry`와 연계) |

### 4-2. 제작소 (가칭) — 연금술 영역

건설된 선실에서 **항공 건축 재료를 소모해 아이템을 제작**한다.
성격상 **SPD 원본 연금술(Alchemy)의 영역**을 대체·수용한다.

| 항목 | 내용 |
|------|------|
| 입력 | 항공 건축 재료 |
| 산출 | 소모품 등 (품목 **미확정**) |
| 사용 범위 | **해당 런에서만 사용 가능** — 일반 소모품과 동일하게 런 종료 시 소멸 |
| 제작 개수 | 제한 없음 (재료가 허용하는 만큼) |

### 4-3. 함선 업그레이드 (상시 지원 효과)

건축 재료로 제강호 자체를 강화하면, **탐색 중 제강호의 지원을 받는다**는 설정으로 이로운 효과를 얻는다.

**설계 방향 (확정)**: 주요 스탯(HP·공격력 등 핵심 축)은 건드리지 않는다.
**"소소하지만 확실한 이득"** — 쿨타임이 길거나 발동 빈도가 낮아 누적 영향이 제한적인 지점을 강화한다.

| 유형 | 예시 | 비고 |
|------|------|------|
| 저빈도 수치 | **궁극기 피해 +1** | 쿨타임이 길어 DPS 영향 미미, 체감은 확실 |
| 시작 보급 | 시작 시 식량 +1 | 파워 인플레 완만 |
| 편의 | 시작 소지금 증가 | 난이도 영향 적음 |
| 지원 (검토) | N층마다 보급 드랍 | 설정 부합도 높음 |

> 주요 스탯을 피하더라도 **항목별 최대 레벨은 필요하다**.
> "궁극기 피해 +1"도 10회 누적되면 +10이 되므로, 상한 없이 두면 결국 같은 문제가 발생한다.

### 4-4. 제작 의뢰소 (가칭) — 탐색 재료 → 다음 런 아이템

탐색 중 얻은 재료를 제강호에 맡겨 **바로 다음 런에서 완성품을 들고 시작**한다.

```
[런 N]    메밀꽃 씨앗 획득 → 재배 의뢰
[런 N+1]  시작 인벤토리에 메밀꽃 약 1개 보유
```

| 항목 | 내용 |
|------|------|
| 입력 | 탐색 중 획득한 재료 (씨앗·특정 아이템) |
| 산출 | 대응 완성품 (약 등) |
| **의뢰 슬롯** | **동시 1개만** — 한 번에 하나의 아이템만 의뢰 가능 |
| 수령 | **바로 다음 런 시작 시** |
| 특징 | 시간차 보상 — 현재 런이 아닌 미래 런에 투자 |

#### 규칙 (확정)

| 항목 | 규칙 |
|------|------|
| 재료 반입 | **생환해야 반입 가능** — 사망 시 인벤토리의 탐색 재료는 소실 |
| 슬롯 수 | 동시 **1개** |
| 슬롯이 찬 상태에서 재의뢰 | **덮어쓰기** |
| 의뢰 취소 | **불가** |
| **제작 완료 시점** | **해당 런의 세이브 데이터가 삭제되는 시점** (사망 또는 엔딩) |
| 지급 시점 | 그 다음 **신규 런** 시작 시 |

> 핵심: 의뢰를 걸어둔 런이 **끝나야** 완성품이 슬롯에 들어간다.
> 런이 살아있는 동안에는 완성품이 존재하지 않으므로, 같은 런에서 회수할 수 없다.

#### 구현 방식 (확정)

상태가 둘이므로 **변수 2개**로 나눈다.

```
pendingRequest   : Item   // 의뢰 접수됨 (런 진행 중, 아직 미완성)
readyProduction  : Item   // 제작 완료 — 다음 신규 런에서 지급 대기

[의뢰]        pendingRequest = <완성품>          // 덮어쓰기 허용, 취소 불가

[런 종료]     if (pendingRequest != null) {      // 사망 / 엔딩 = 세이브 삭제 시점
                  readyProduction = pendingRequest;
                  pendingRequest  = null;
              }

[신규 런 시작] if (readyProduction != null) {     // initFromOperator 시점
                  지급(readyProduction);
                  readyProduction = null;
              }
```

4-2(제작소)와의 차이는 **입력 자원**과 **수량 제한**이다.

| | 제작소 (4-2) | 제작 의뢰소 (4-4) |
|---|---|---|
| 입력 | 항공 건축 재료 | 탐색 중 획득 재료 (**생환 필요**) |
| 수량 | 제한 없음 | **동시 1개** (덮어쓰기, 취소 불가) |
| 사용 시점 | 해당 런 | **다음 런** |

---

### 4-5. 제강호 접속 수단

4-4가 "생환 필요"이므로, **재료를 안전하게 반입할 경로**가 필요하다.

| 수단 | 내용 |
|------|------|
| **클리어 후 귀환** | 최종 보스 처치 시점에 제강호로 비교적 손쉽게 복귀하는 기능 |
| **통신 소비 아이템** | 탐색 중 사용 → "제강호와 통신·물품 전송" 개념으로 **런 도중 제강호 시스템 접속** |

> 통신 아이템은 **위험 부담(전멸 시 재료 소실)을 줄이는 보험**이자,
> 소지 여부에 따라 "지금 돌아갈까, 더 들어갈까"라는 판단을 만드는 장치다.

## 5. 데이터 저장 설계

메타 진행은 **세이브 파일이 아닌 전역 파일**에 저장한다 (런 사망과 무관하게 유지).

### 기존 선례 활용

이미 `OperatorRegistry`가 동일 패턴을 쓰고 있다:

```java
public static final String REGISTRY_FILE = "operators.dat";
FileUtils.bundleFromFile(REGISTRY_FILE);   // 로드
FileUtils.bundleToFile(REGISTRY_FILE, b);  // 저장
```

### 제안 구조

**`jiganghao.dat`** (신규 전역 번들)

| 키 | 타입 | 내용 |
|----|------|------|
| `materials` | int | 보유 항공 건축 재료 |
| `builtRooms` | String[] | 건설 완료 선실 ID 목록 |
| `upgrades` | Bundle | 업그레이드 항목별 레벨 |
| **`pendingRequest`** | Bundle | **의뢰 접수 (런 진행 중, 미완성)** |
| **`readyProduction`** | Bundle | **제작 완료 — 다음 신규 런 시작 시 지급 후 비움** |
| `storedMaterials` | Bundle | 반입된 탐색 재료 재고 |

> `Item`은 `Bundlable`이라 `bundle.put(key, item)` / `bundle.get(key)`로 **객체를 통째로**
> 직렬화할 수 있다. 별도 ID 매핑 테이블이 필요 없다.

### ⚠️ 세이브 슬롯 관련 — 코드 검증 결과

**"런 A에서 의뢰 → 런 B 세이브를 로드하면 즉시 지급되는" 문제는 발생하지 않는다.**

| 경로 | 시작 아이템 지급 |
|------|-----------------|
| `Dungeon.init()` → `hero.initFromOperator()` | ✅ **신규 런 생성 시에만** 실행 |
| `Dungeon.loadGame()` | ❌ 지급 로직을 전혀 타지 않음 |

기존 세이브를 불러오는 것은 **완전히 별개 경로**라, 이미 진행 중인 런 B가 아이템을 받을 일이 없다.
여기에 4-4의 "런 종료 시 제작" 규칙까지 더해지면, 런 A가 살아있는 동안에는
`readyProduction` 자체가 비어 있으므로 **이중으로 차단**된다.

**남는 특성** (의도 확인 필요): 제강호 데이터는 전역이므로, 런 A 종료 후 완성품은
**그 다음에 새로 시작하는 런**(슬롯 무관)이 가져간다.

> 단순 수치 하나(재료 개수)라면 `SPDSettings` 키로도 충분하지만,
> 선실·업그레이드·대기 아이템까지 다루므로 **전용 번들 파일이 적합**하다.

## 6. 구현 훅 (코드 지점)

| 기능 | 붙일 위치 |
|------|----------|
| 재료 획득 | 보스 `die()` — 예: `actors/mobs/endfield/Rodan.java` (부적 드랍부 참고) |
| 재료 적립 | 드랍 아이템의 `doPickUp()` → `Jiganghao.addMaterials(n)` |
| **다음 런 아이템 지급** | `Hero.initFromOperator()` — `Dungeon.init()`에서 **신규 런에만** 호출됨 |
| 시작 보급 업그레이드 | 동일 (`initFromOperator`) |
| **런 종료 → 제작 완료** | `Dungeon.fail()` / `Dungeon.win()` — 사망·엔딩 양쪽을 모두 지나는 지점 |
| **재화 보유량 표시** | `windows/WndGame.java` (인게임 ESC 메뉴) + 제강호 화면 |
| 제강호 화면 | 신규 `scenes/JiganghaoScene` (→ 7절 결정 필요) |
| 영구 저장 | `Jiganghao.loadGlobal()/saveGlobal()` — `OperatorRegistry` 복제 |

> `Dungeon.deleteGame()`도 런 종료 경로지만, **수동 세이브 삭제**(`WndGameInProgress`)도
> 같은 함수를 타므로 부적절하다. 사망/엔딩만 잡으려면 `fail()`/`win()`이 정확하다.

## 7. 미확정 — 결정 필요 목록

### 확정된 항목

| 항목 | 결정 |
|------|------|
| 탐색 재료 회수 | **생환해야 반입** (사망 시 소실) + 통신 아이템/클리어 귀환으로 보완 (4-5) |
| 의뢰 슬롯 | 동시 1개 · 덮어쓰기 허용 · 취소 불가 · **런 종료 시 제작** |
| 세이브 슬롯 | **전역 공유** (진행 중인 다른 런에 새지 않음 — 5절 검증 참조) |
| 재화 표시 | 인게임 ESC 메뉴(`WndGame`) + 제강호 화면 |
| 영구 강화 방향 | 주요 스탯 배제, 저빈도 수치(궁극기 피해 등) 중심 |

### 남은 미확정

| # | 항목 | 선택지 / 비고 |
|---|------|--------------|
| **1** | **제강호 접근 방식** | (a) 타이틀/시작 화면에서 별도 씬 (b) 던전 0층 등 인게임 공간 (c) 런 종료 직후 정산 화면 |
| 2 | 경제 페이싱 | 런당 획득량 ↔ 비용. **후순위** — 시스템 구현 후 플레이하며 조정 |
| 3 | 업그레이드 상한 | 항목별 최대 레벨 (4-3 주석 참조) |
| 4 | 재료 획득처 범위 | 보스 전용 vs 미니보스·층 도달 포함 |
| 5 | 오퍼레이터 해금 연동 | 건축 재료로 해금 vs 현행 `OperatorRegistry` 조건 유지(별개) |
| 6 | 선실 목록 확정 | 4-1 후보 표 참조 |
| 7 | 제작 품목 확정 | 4-2 산출물 · 4-4 재료↔완성품 대응표 |
| 8 | 통신 아이템 수급 | 4-5. 상점 구매 / 드랍 / 제작소 생산 |
| 9 | 의뢰 중 세이브 수동 삭제 | 런을 포기(수동 삭제)해도 제작 완료로 칠 것인가 (기본: 아니오) |

## 8. 구현 단계 제안

작은 것부터 굴려보며 확장하는 순서.

| 단계 | 범위 | 비고 |
|------|------|------|
| **1** | 재화만 구현 — 로댄이 재료 드랍 → 획득 시 영구 적립 → 타이틀에 보유량 표시 | 로그라이트 루프의 최소 성립 |
| **2** | 제강호 씬 + 함선 업그레이드 1종 (시작 식량 +1) | `initHero` 훅 검증 |
| **3** | 선실 건설 + 제작실(4-2) | |
| **4** | 재배실 + 의뢰 제작(4-4) | 탐색 재료 반입 구조 필요 |
| **5** | 선실 확장 / 업그레이드 다양화 | |

> 현재 A1~A5 테스트 빌드 기준으로는 **1단계만 넣어도** "로댄 처치 → 재료 획득 → 다음 런에 활용"
> 이라는 로그라이트 사이클이 성립한다.
